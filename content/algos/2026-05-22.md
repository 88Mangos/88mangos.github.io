# The Daily (Easy): `1752. Check if Array Is Sorted and Rotated`
Here is my solution:
```python
class Solution:
    def check(self, nums: List[int]) -> bool:
        n = len(nums)
        diffs = [(nums[i] - nums[i-1]) < 0 for i in range(n)]
        # print(sum(diffs))

        return sum(diffs) == 1 or sum(diffs) == 0
```
in essence, you just make sure there's only one inflection point (where the next item is greater than the prev, i.e., breaks monotonically increasing order), or there are no inflection points, i.e., all items are the same.

# A greater challenge: `4. Median of Two Sorted Arrays`

Since the TC needs to be $O(\log (m + n))$, the solution is sort sort of divide and conquer.

### Maybe we can somehow strengthen the subproblem?
Again, the recurrence we want is $W(m+n) = W((m + n) / 2) + O(1)$, same recurrence as binary search. 

We can strengthen the subproblem by passing in `m, n, ignored_left, ignored_right`

so let's work through our two cases using this:

Odd Case:
```sh
# m = 3, n = 4, ignored_left = 0, ignored_right = 0
[1, 3, 5], [2, 4, 6, 8] == [1, 2, 3, 4, 5, 6, 8]
# m = 2, n = 1, ignored_left = 2, ignored_right = 2
=> [3, 5], [4] == [3, 4, 5]
# m = 0, n = 1, ignored_left = 3, ignored_right = 3
=> [], [4] == [4]
=> 4
```
Candidate invariant, `ignored_left` and `ignored_right` are equal.

Even Case:
```sh
# m = 3, n = 5, ignored_left = 0, ignored_right = 0
# lo1 = 0, lo2 = 0
# hi1 = 2, hi2 = 4
[1, 3, 5], [2, 4, 6, 8, 10] == [1, 2, 3, 4, 5, 6, 8, 10]

# m' = 2, n' = 2, ignored_left = 2, ignored_right = 2
# lo1 = 1, lo2 = 1
# hi1 = 2, hi2 = 2
=> [3, 5], [4, 6] == [3, 4, 5, 6]

# m'' = 1, n'' = 1, ignored_left = 3, ignored_right = 3
# lo1 = 1, lo2 = 2
# hi1 = 1, hi2 = 2
=> [5], [4] == [4, 5]
=> 4.5 
```
The trouble is that `ignored_left` and `ignored_right` are computable from the original `m` and `n`. It's also not any better than my previous idea.

### Any sort of visual intuitions?
We can think of both of the nums arrays as being concatenated and slowly shrinking, and swapping positions as needed.

```sh
[1, 3, 5], [2, 4, 6, 8, 10] == [1, 2, 3, 4, 5, 6, 8, 10]
=> [3, 5], [4, 6] == [3, 4, 5, 6]
=> [5], [4] 
=> [4], [5] == [4, 5]
=> 4.5 
```

```sh
[1, 3, 8], [2, 4, 5, 6, 10] == [1, 2, 3, 4, 5, 6, 8, 10]
=> [3], [4, 5, 6] == [3, 4, 5, 6]
=> [], [4, 5] == [4, 5]
=> 4.5 
```
So clearly, we have an easy base case: if our left or right array is empty, return median of the other one.

However, the swapping logic is slightly complicated? 
We know `nums1` needs to shrink by `len(nums1) // 2` and `nums2` needs to shrink by `len(nums2) // 2`, but we may not necessarily go to the median of either - we can take from either side.

There's only one true way to do it such that it's mathematically correct to maintain the median of the big overall combined array,
however, it would be complicated to iterate through the possible ways to take from both sides. That would ruin our recurrence with $O(1)$ nonrecursive work per level.
